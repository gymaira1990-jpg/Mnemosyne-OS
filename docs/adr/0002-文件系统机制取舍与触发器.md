# ADR-0002 · 文件系统机制取舍与触发器

- **状态**：已接受（Accepted）
- **日期**：2026-09-25
- **决策者**：G-CAT（确权）+ EN-诺亚（提案）
- **关联**：提案 [P-20260925-01](../../openspec/changes/2026-09-25-v8-memory-os/proposal.md) · 前一轮研究 `~/memfs-8.0-team/` · 原报告《记忆文件系统（Memory FS）——统一架构研究报告》

## 背景

2026-09-24 一份 193KB 的《记忆文件系统研究报告》提出把文件系统 40 年工程原理（20 个维度：inode / extent / dentry / B+树 / journal / COW / checksum / 快照 / 硬链接 / 页缓存 / delalloc / defrag / GC / 配额 / ACL / LFS / RAID / mount / barrier / 反向引用）迁移到 Mnemosyne-OS。

前一轮专项组做了三项交叉验证，结论**大幅收窄了范围**：

1. **代码锚点回查**：报告 10/10 抽验命中 → 报告的**现状诊断是准的**，值得采信。
2. **红队 6 条质疑**：多数机制对当前规模（1.5 万条）是**规模错配或重复劳动**；且 PostgreSQL **已经提供了**其中大部分（WAL / MVCC / shared buffer / btree）。
3. **FS 可行性官逐条判定**：20 维里 **8 维可迁 / 11 维需变形 / 1 维不行（RAID）**；真正缺的只有三类 —— **生命周期回收、引用完整性、行级权限**。

同时，报告**自己**在每一维都标了边界与反例，并自设门槛（如「>500 万行或正文 >4KB 才拆表」）。

## 决策

### 1. 采纳（进 v8.0 实施）

| 机制 | 为什么采纳 |
|---|---|
| **写入原子性**（journal 的语义，不是 journal 的表） | 唯一有「数据会错」后果的真缺陷：非原子写入 + 无幂等 → 崩溃留半成品、重试重复入库 |
| **生命周期回收 GC + compaction** | 全仓无 DELETE / 无 VACUUM，软删即终点。这是 FS 机制里**真正缺**且**当前规模就疼**的一件 |
| **引用完整性**（引用归零才回收） | 回收的前置安全条件，不做则 GC 会删掉还被引用的记忆 |
| **召回融合 RRF**（目录查找 + 内容索引分层的**收益部分**） | 四通道结果不融合是召回质量天花板的真实瓶颈，且**已有验证过的实现**（WIKI 路径） |
| **端到端校验**（内容哈希 / embedding 版本戳） | 只做**只读 scrub 报告**，不做自动修复 —— 低风险高收益 |

### 2. 明确不做（本 ADR 的核心价值）

| 机制 | 不做的理由 |
|---|---|
| `memory_inode` 元数据与内容拆表 | 当前 1.5 万行不需要；且拆表是**不可逆**结构变更，收益要等规模 |
| `memory_wal` 应用层写入日志 | **重复发明 PostgreSQL 事务**。报告自己承认 PG 有 WAL，仍要应用层再做一层 = 写放大无收益 |
| `archive_directory` 档号目录树 / B+树 | 九翼×约 20 房 ≈ 180 叶，btree 无区分度；真问题只是一行取模碰撞，单独修即可 |
| 块级快照回滚 / 时间点恢复 | 单用户无强隔离需求；COW 的空间 accounting 复杂度远超收益 |
| 配额系统 / 多租户隔离重构 | 概念偷换：当前只有一个真实租户，无强隔离需求 |
| 内容 / embedding 物理分离（extent） | <500 万行前是过度工程 |
| 页缓存调优 / defrag / 向量时钟 | DB 自带 shared buffer，不要双份缓存；SSD 上传统 defrag 失效；单用户 LWW 足够 |
| RAID / 纠删码 | 块层机制，跨机一致性靠 LWW + 幂等键，不能照搬 |

### 3. 触发器（本 ADR 的**执行条款**）

> **未触发不得新增上述任何被否决的机制。** 触发时先回到本 ADR，重新评估并记录新 ADR，不许"顺手加上"。

| 触发器 | 阈值 | 触发后解锁 |
|---|---|---|
| T-1 表规模 | `memories` 单表 **> 500 万行** | `memory_inode` 拆表 · `memory_extent` 物理分离 |
| T-2 正文体积 | 正文平均 **> 4KB** | 内容/向量物理分离 + 压缩 |
| T-3 真实多租户 | 出现**第二个真实租户**（非同名收敛） | 配额系统 · 租户隔离重构 |
| T-4 档号碰撞 | `archive_no` 实际碰撞 ≥ 1 次（不只是理论风险） | 档号目录树 |
| T-5 删除事故 | 发生 1 次**误删且不可恢复** | 块级快照 / 时间点回滚 |

**当前实测（2026-09-25）**：表 ≈ 1.6 万行 · 正文均值 <1KB · 单租户 · 无碰撞记录 · 无删除事故 → **五项全未触发**。

## 后果

**正面**：
- 把「研究 → 一大本报告」收敛成「**4 件真缺陷 + 1 件可测量优化**」，避免 8.0 变成 20 维并行改造的泥潭
- 原报告的价值被**制度化保留**：它的边界条件变成了我们的闸门 —— 既没浪费那份研究，也没被它牵着走
- 未来规模变化时，有明确的**重新评估入口**（触发器），不靠人记得

**负面 / 风险**：
- 若规模远超预期地增长，可能在触发之前就先感到性能压力（缓解：`S1-4` 埋点提供实测 p95，压力可见）
- 触发器阈值是经验值，可能需要按实测调整（缓解：阈值本身就是 ADR 可修订条款）

**被否决方案**：全量照搬 20 维（红队判定为规模错配 + 重复劳动）；也否决「什么都不做」（S1-1/S1-2/S1-3 是真实缺陷）。
