# Mnemosyne OS v6.3 设计：认知写入信号

> 2026-08-05 | 设计来源: 诺亚三代「抽屉级联压缩引擎」温度设计（重要性加分表, 代码锁死不靠LLM）

## 背景

v6.2 已解决"搜索命中不加热"（热度有使用信号）。但**写入端仍无认知信号**：
- 所有记忆写入 heat=0.5（蒸馏 0.65），"未完成任务"和"寒暄记录"初始热度相同
- 热度衰减一视同仁，重要知识会被时间冲淡

抽屉级联的温度设计（诺亚三代实战验证）:
```
未完成任务 +5 | 用户纠正 +4 | 决策记录 +3 | 情绪波动 +3
路径/API变更 +2 | 工具结果 +1 | 寒暄/确认 0
```

## 改动清单

### 1. 写入重要性信号 (main.py create_memory)
- 写入时对 content 做纯正则信号检测（代码锁死，不调 LLM）:
  | 信号 | 正则关键词 | heat 加分 |
  |:-----|:----------|:---------:|
  | 未完成任务 | 待办/下一步/TODO/pending/未完成 | +0.15 |
  | 用户纠正 | 不是/错了/不要/应该/修正/记住 | +0.10 |
  | 踩坑教训 | 坑/教训/报错/失败/注意/踩过 | +0.10 |
  | 决策方案 | 决定/方案/采用/架构/设计 | +0.08 |
  | 路径/API | 路径/端口/API/配置/key | +0.05 |
  | 重要标记 | 重要/关键/核心/必须 | +0.05 |
- category 加成: preference/knowledge/pitfall → +0.10 (天生重要)
- 初始 heat = clamp(0.5 + 信号加分 + 类别加成, 0.3, 0.8)

### 2. 重要记忆保护衰减 (tmt/router.py tmt_decay)
- pinned 记忆 (metadata.pinned=true) 或 preference 类 → 衰减 ×0.995
- 其余 → 近 48h 活跃 ×0.995 / 普通 ×0.98 (v6.2 保留)
- 效果: 用户偏好/重要知识长期保持热度

### 3. 蒸馏入库热度联动 (tmt/distill.py)
- 蒸馏 summary 含"坑/教训" → heat 0.70 (pitfall 天生重要)
- 其余保持 0.65

## 验证方案
1. 写入"待办: xxx" → heat ≥ 0.65; 写入寒暄 → heat ≈ 0.5
2. decay 后: preference 衰减 < 普通记忆
3. 蒸馏 pitfall 入库 heat=0.70
