# Mnemosyne OS v6.2 设计：认知热度引擎 + 蒸馏增强

> 2026-08-05 | 设计来源: 爆炸遗产考古 (noah 双权重热度公式 / soft-context 前额叶索引表 / 备份守则 SAB 分级)

## 背景与问题

实测 (2026-08-05):
- `avg_heat_score = 0.10`，L1 热点记忆仅 1 条 (stats 口径)
- **根因**: 热度只有"初始值 0.5 + 纯乘法衰减 (0.98/4h)"，没有任何"使用"信号——搜索命中不更新 access_count，不加热度
- 记忆越用越冷，跨会话"什么重要"感知钝化

## 改动清单

### 1. 搜索命中加热 (main.py search_memories)
- 位置: hybrid 分支 + created_at 分支，rows 返回前
- 行为: 命中结果 top 5 → `access_count+1, last_accessed=NOW(), heat_score=LEAST(1.0, heat+0.05)`
- 概念来源: noah 双权重热度的"访问频次"分量 (0.4 权重)

### 2. 召回命中加热 (tmt/router.py tmt_recall)
- 位置: candidates 汇总后
- 行为: 最终候选 top 3 (src=memories) 加热同上

### 3. 差异化衰减 (tmt/router.py tmt_decay)
- 位置: memories 表 UPDATE
- 行为: `CASE WHEN last_accessed > NOW()-48h THEN heat*0.995 ELSE heat*0.98 END`
- 概念来源: 热度"时间衰减"分量——活跃记忆衰减慢 2.5 倍，保持热点

### 4. 蒸馏入库热度信号 (tmt/distill.py)
- 蒸馏出的 knowledge/pitfall 入库 heat=0.65 (默认 0.5 → 0.65，"新知识"初始信号)
- 批内去重: 同批相似 summary 互查，避免同批重复提炼

### 5. 备份守则对照 (GZ backup.sh)
- noah 备份守则: S级(记忆/技能/配置必须备份) vs B级(可重装不备份)
- 检查 backup.sh 是否覆盖: PG 数据 + 仓库 + .env + 技能

## 验证方案
1. 造记忆 → 搜索命中 → heat 提升断言
2. 手动 decay → 近访问 vs 远访问衰减差异断言
3. distill 批内去重: 两条相似候选 → 第二条跳过断言
4. avg_heat / L1 热点数统计变化
