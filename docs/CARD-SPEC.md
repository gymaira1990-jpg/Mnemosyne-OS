# Card Spec v1 —— 著录卡规范

> 版本: v1（2026-11-04，随 9.0.10 发布）｜机器校验: `python3 scripts/card_check.py`
>
> 这份规范回答一个问题：**什么样的东西才算一张卡**。
> 它不描述数据库字段（那在 `docs/schema.sql`），只描述**卡片正文**——
> 也就是你在库里 `memories.content` 里读到的那 7 行。

---

## 0. 为什么要规范

一句话：**卡片是索引，不是摘要。** 摘要是给当下看的，卡片是给三个月后的自己检索、追溯、反驳用的。

所以规范的判据不是「写得漂亮」，而是：

1. **能被找到**（有档号、有标签、有原子事实）
2. **能被验证**（有证据指针，且指向不会消失的东西）
3. **能回到现场**（有 `sid`，能跳回原始对话）

三条任一缺失，这张卡就只是「一段感想」，不该占用手册的位置。

## 1. 结构（7 行，顺序固定）

```
[结果卡] 档号：K·GEN·2026-0841
题名：修 SVG 箭头不显示
摘要：定位到 marker 的 id 与 defs 里的引用对不上，改成显式 url(#id) 后箭头正常显示，回归了同页另外两处图标。
实体：v9.0.10 · T-0642 · docs/CARD-SPEC.md
证据：T-0642 · 64624c6 · docs/CARD-SPEC.md
标签：svg 前端 修复
来源：sid=2f1c9a3e-7b41-4c8e-9d2a-0f6b5c1e8a77
```

| 行 | 必须 | 说明 |
|---|---|---|
| `[结果卡] 档号：` | ✅ | 固定前缀，档号在**首行**（检索锚点就在这一行） |
| `题名：` | ✅ | 4–80 字，是名词短语不是句子（不带句末标点） |
| `摘要：` | ✅ | 40–600 字，只写**发生了什么**，不写计划/判断 |
| `实体：` | 可选 | 原子事实行，由规则抽取，不是人写的散文 |
| `证据：` | ✅ | 1–6 项，`·` 分隔，每项 ≤140 字，指向**持久**的东西 |
| `标签：` | ✅ | 1–8 个，空格分隔，检索用 |
| `来源：` | ✅ | `sid=<会话 id>`，两级跳追溯的锚 |

> `实体` 行允许省略（没抽到原子事实时）。8.x 时代的卡把它写在末尾——校验器会给一条提醒而不是判红。

---

## 2. 档号：编号即位置

格式：`K·<项目>·<年>-<四位序号>`　例：`K·GEN·2026-0841`

- `K` = 卡（固定）
- `<项目>` = 大写字母开头、≤10 位的项目代号（`GEN` / `MEMO` / `DIARY` / `CARD` / `GAME`…）
- `<年>` = 该卡所属年份（取会话日期，不取写入时刻）
- `<序号>` = 该项目该年内的流水号，**从 0001 起，四位补零**

**三条硬约束**（都踩过）：

1. **档号只由机器生成，模型一个字都不许改。** 模型可以润色摘要措辞，碰档号就等于伪造法律文书的编号。
2. **重灌必须带 `--seq-offset`。** 生成器每次从 0001 起编，重跑一遍就与上一批撞号，新旧两套会互相覆盖检索结果。
3. **档号在正文首行，同时写进 `archive_no` 列。** 只写列不写正文 ⇒ 语义/关键词通道看不见它；只写正文不写列 ⇒ 精确通道查不到。

---

## 3. 摘要：写结果，不写心情

- **长度** 40–600 字。短于 40 基本是「修好了」这种废话；长于 600 说明你把对话粘进来了。
- **只写已发生的事**：做了什么、改了什么、实测结果是什么。
- **禁止的词**：`待补` / `TODO` / `下一步` / `应该会` / `预计` —— 出现这些词说明你在写计划。计划进台账（`gcat-track`），不进卡片。
- **数字要带单位与口径**：「回归 12 项全过」优于「测试通过」；「294 passed / 0 skipped」优于「测试都过了」。

---

## 4. 证据：分级 + 清洗 + 上限

### 4.1 分级（排序用，越靠前越持久）

| 级 | 形态 | 例 |
|---|---|---|
| 0 | 台账卡号 | `T-0642` |
| 1 | git 提交 hash | `64624c6` |
| 2 | 仓库内文件 | `docs/CARD-SPEC.md` |
| 3 | URL | `https://…` |
| 4 | 绝对路径 | `~/.hermes/scripts/x.sh` |
| — | **一次性目录（禁止）** | `/scratch/`、`/cache/`、`/tmp/`、`/.hermes/data/digest/` |

**为什么要分级**：抽 3 张卡核验时发现 2 张的证据指向 `scratch/hermes-verify-*.py` —— 那是跑完即删的探针文件，等于没有证据。**指向会消失的东西，不算证据。**

### 4.2 清洗（三刀，缺一刀就会漏）

1. 去掉包裹的引号/反引号/括号
2. 超长丢（>140 字 ⇒ 几乎一定是吞了整句话）
3. 含句末标点（`。！？`）丢 —— 那是句子片段，不是指针

### 4.3 抽取时的字符类陷阱

写正则捞 URL / 路径时，**别用 `\S+` 或 `[\w.\-/]`**：Python 的 `\w` **包含中文**，会一路吞进句子里，
抓出 `http://127.0.0.1:9223\`？我建议不改**——保持 · ~/.hermes/scripts/…` 这种不是证据的东西。

- URL 用**显式 ASCII 集**：`[A-Za-z0-9._~:/?#\[\]@!$&'()*+,;=%-]`
- 路径用**否定类**：`[^\s`'"<>）】」，。；：、]`

## 5. 实体行：原子事实，0 token 抽出来

形态：`实体：<值1> · <值2> · <值3>`

只收**原子事实**：版本号、台账号、提交 hash、路径、纯数字指标。不收人名、地名这类软信息（容易错，也检索不动）。

它放在**证据之前**：召回时最有用，而且纯规则抽取，不花 token、不引入模型幻觉。

---

## 6. 向量化：只喂「题名 + 标签」

🔴 **这是全套规范里最容易做错、代价也最大的一条。**

| 进向量的内容 | 字数 | 精确集 | 模糊集 |
|---|---|---|---|
| 整条 content | 538 | 70% | 60% |
| 题名 + 标签 + 首句 | ~80 | — | 50% |
| **题名 + 标签（纯索引）** | **28** | **80%** | **90%** |

正文进向量会**稀释语义**：概念词查得准，口语整句退化成字面相似。三档实测下来，28 字那档胜出，且比整条正文高 20 个点。

⚠️ **与当前实现的差异（必须知道）**：
`POST /api/v1/memories` 默认对 `content` 做 embedding。生产库里的卡片向量是**回填脚本按"题名+标签"重算**的（绕过 API 直写 `embedding` 列）。
⇒ 如果你直接调 API 灌卡，拿到的是「正文向量」，召回表现会退回上表第一行。
⇒ 改向量化文本后**必须全量重算**；完成判据不是「向量非空」（它一直是满的），而是**评测集重测召回**。

---

## 7. 追溯：档号 → 卡 → sid → 原文

```
档号（精确，可读） → 卡片正文 → sid（会话 id） → 原始对话
```

- 向量索引是**近似**的，档号不是。
- 拿档号去问语义检索**天然无效**（向量比的是「意思相近」），必须走 SQL / `/exact`。
- 因此：**检索器要先判形态**（档号 / 台账号 / 提交 hash / 路径 vs 自然语言），精确形态直落 SQL。

---

## 8. 不合格卡的形态（反面清单）

| 形态 | 为什么不行 |
|---|---|
| 只有摘要没有证据行 | 无法验证 ⇒ 只是感想 |
| 证据指向 `scratch/` `tmp/` | 文件已删，追溯断链 |
| 证据是一句带句号的话 | 那是句子片段，不是指针 |
| 摘要里写「应该/预计/下一步」 | 记的是计划不是结果，三个月后会被当成事实 |
| 模型改写了档号/证据/实体行 | 卡片是法律文书，模型只许润色措辞 |
| 题名是一整句（带句号） | 检索时匹配不到名词短语 |
| 一张卡塞 10 条证据 | 噪声压过信号，排序反而变差 |

## 9. 参考实现与现状差异

| 实现 | 位置 | 说明 |
|---|---|---|
| **最小示例（公开仓）** | `integrations/card-builder/` | 纯标准库，演示「对话 → 卡」的全链路，可跑通 |
| **生产实现（私有侧）** | 作者工作区 | 多一层：会话切分策略、标题优选、精修作业、判重 |
| **校验器** | `scripts/card_check.py` | 本规范的判据实现，含正反例自检 |

示例与生产实现的差异是**有意的**：公开仓给的是「能照着做的骨架」，生产侧那层是针对真实语料磨出来的调优，不随仓库发。

## 10. 自检

```bash
python3 scripts/card_check.py --selftest        # 正例必须过，6 个反例必须判红
python3 scripts/card_check.py <卡片文件>         # 校验一张卡
cat card.txt | python3 scripts/card_check.py -  # 从 stdin
```

`make test` 会调用它；不合格的卡不要入库。
