# Mnemosyne OS v6.4 设计：事实提取管道 (Fact Extraction Pipeline)

> 2026-08-05 | 立项依据: LongMemEval 归因结论 (#6293) — 真实差距 = 缺"事实提取"层

## 背景

LongMemEval 评测证明: Mnemosyne 检索核心健康, 但「事实级记忆」缺失——
外部产品 (Mem0) 用 extract-and-retrieve 把对话压平成 facts 再检索,
我们的 distill 只提炼「知识/坑」, 没有「个人信息 facts」(毕业/通勤/轮班/偏好)。
评测直接检索原始对话 = 大海捞针 (sim 0.2), 16.7%。

## 目标

对话记忆 (session/worklog) → 事实提取 → 用户画像 facts (preference/knowledge) → 可检索。

## 设计要点 (全部来自评测教训)

1. **短文本逐条提取**: 每条记忆独立调 LLM, 不拼接长上下文
   (豆包 lite 对 1.3 万字符长会话漏深处答案, 但短文本提取可靠)
2. **非 json 模式**: call_llm 输出 "- fact" 行格式, 正则解析
   (豆包 json_mode 长 prompt >2500 字符返回空 — 已实测)
3. **tier3 lite**: 便宜够用 (提取是简单任务)
4. **只提取不编造**: prompt 硬约束 + 规则明确
5. **ANN 去重闸机**: 复用 distill dedup_check (>0.92)
6. **热度 0.65**: 提取的事实是功能记忆, 天生重要
7. **溯源**: metadata fact_extracted_from / fact_extracted_at / source_category
8. **失败重捞**: LLM 空返回不标记, 下轮 cron 重试

## 实现: tmt/factextract.py

```
候选筛选: category IN (session,worklog) AND metadata->>'fact_extracted' IS NULL
  → 每条: 信号过滤(寒暄跳过) → extract_facts(content) → 逐fact去重+入库
  → 标记源 fact_extracted=true
分类: 偏好/个人信息关键词 → preference; 其他 → knowledge
用法: python tmt/factextract.py [--batch N] [--dry-run]
```

## 验证

1. 本地 mock: 提取解析/分类/去重逻辑
2. GZ dry-run: 真实数据 20 条
3. LongMemEval B 组复测: 提取层正确实现后, 分数应显著提升 (目标 ≥40%)

## 不做 (实用原则)

- 不做图谱化 (AGE 已有, 事实层先用扁平行)
- 不做全量重算 (从新数据开始)
- 不依赖 json_mode / tier4 code
